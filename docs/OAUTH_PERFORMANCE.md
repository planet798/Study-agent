# 订阅请求性能与流式显示

桥接使用最多两个按配置隔离的 Node 进程。应用后台预热当前订阅配置，后续请求复用进程与 SDK 连接；登录使用独立可取消进程。
请求 ID 区分结果与事件，进程崩溃或超时不会自动重发已经发送的模型请求，下一次显式请求重新启动组件。退出应用释放桥接进程。

每次调用从系统存储读取最新凭据，同配置的刷新过程串行。只有凭据发生变化才写系统存储；刷新事件立即保存，即使后续请求失败也保留新凭据。凭据不写数据库、日志或计时报告。

对话增量只显示文本，不显示模型思考或工具参数。增量在内存暂存，结束后由原有文档面板呈现；消息持久化、工具和审批仍走原 Runtime。会话/worker 标识过滤过期事件，用户阅读历史时不强制跳到流式消息。

设置页的“首字”从用户发起测试到首个文本事件，“完整”从发起测试到完整结果交付；原 `latency_ms` 仍表示总耗时，排队和认证时间也计入。选择配置和“设为当前”是不同操作，连接测试针对选中的配置。

## 可重复离线基准

在有 Node.js 和桥接生产依赖的 WSL/Linux 或 Windows 环境执行：

```text
python scripts/benchmark_bridge.py --output build/bridge-benchmark.json
```

2026-10-04 WSL、Node.js 22.19.0、SDK 1.0.0、五次离线目录查询：

| 指标 | 中位数 |
| --- | ---: |
| 每次独立进程 | 102.29 ms |
| 已预热复用进程 | 1.64 ms |

该基准不请求真实模型，不代表原 7061 ms 模型请求已降至 1.64 ms。真实模型性能应在同账号、模型、提示和网络条件下比较首字与完整请求耗时；不能通过降低推理量、输出量或重命名指标制造改善。
